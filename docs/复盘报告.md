## 一、基础情况

### 1. 项目定位

DanusWin 是把开源 Danus（AI 数学证明搜索多智能体系统）改造为 Windows 原生可运行的桌面版：

- 核心引擎 danus/ 保持上游语义：内容寻址事实图（唯一真相源）、验证器唯一写门、角色权限表（MCP）、BM25 记忆检索、worker 轮询循环、策略咨询环；
- 新增 app/ 层（FastAPI + 中文网页 UI）替代上游 Claude Code 主代理与 bash 运维层，提供项目/worker 管理、设置、事实图浏览、撤销、结题、报告生成；
- 启动Danus.bat 双击即建环境并启动，浏览器打开 http://127.0.0.1:8765。

### 2. 技术栈与版本（实测）

- Python 3.10.9（.venv，基座为 D:\python）
- FastAPI 0.141.1 / uvicorn 0.52.1 / pydantic 2.13.4
- openai 2.53.0 / psutil 7.0.0
- mcp 2.0.0（与上游代码不兼容，见 P0）
- codex CLI 0.146.1（npm @openai/codex；文档声称 0.93.0，见 P2-7）
- 模型：deepseek-v4-flash（worker/验证）、deepseek-v4-pro（策略咨询），provider 走 Responses API

## 三、问题清单（按严重度）

### P0 · 严重

**1. mcp 2.0 不兼容 → MCP 网关不可用（新装环境必坏）**

- 证据：.venv 内 mcp 2.0.0 已移除 mcp.server.fastmcp，而 danus/gateway/server.py 顶部 from mcp.server.fastmcp import FastMCP；实测 import danus.gateway 抛 ModuleNotFoundError。
- 影响：worker/验证器的标准 fact_submit、gm_add、工具注入全部失效。本次 Ramsey 能产出 13 条事实，全靠各 worker 的 codex 模型自救：high 用 danus_api.py（types.ModuleType 伪造 mcp 模块、直接调网关函数）、high2 用 gw.py、xhigh 用 tools/danus_client.py、xhigh2 用 submit_facts.py——这是对角色权限表+唯一写门架构的临时绕行，新建项目/新 worker 会再次坏。
- 修复：pyproject.toml 与 启动Danus.bat 的安装行把 mcp 钉为 mcp>=1.2,<2；或按 mcp 2.x 新 API 迁移网关；随后删除 runtime 里临时绕行脚本，并验证 python -c "import danus.gateway"。

### P1 · 重要

**2. API Key 明文存储 + HTTP 接口回显**

- config/settings.json 明文保存 DeepSeek sk-* 密钥；GET /api/settings 直接返回完整 api_key（已实测回显 35 位）；只有 /api/overview 做了脱敏。
- 修复：GET 一律脱敏；密钥改由环境变量/系统凭据库注入；补 .gitignore；若目录曾外发/上传过，建议立即到 DeepSeek 控制台轮换该 Key。

**3. 无 .gitignore**

- 上游有 .gitignore，本移植没有。.venv/、runtime/（含 codex-home 会话、sqlite）、config/settings.json、_scratch/ 一旦入 git/网盘会被整包同步。

**4. 本地服务无鉴权 / 无 Host-Origin 校验**

- 仅绑定 127.0.0.1，但任意本地进程（或 DNS rebinding 页面）可读设置（含 key）、启停 worker、撤销事实、触发 npm install -g。建议加轻量 Host/Origin 校验中间件。

**5. 孤儿进程问题（本次真实发生）**

- app 退出时 supervisor 无统一清理钩子：verify + 4 个 worker 变成孤儿继续空转、烧 DeepSeek 额度数小时。
- 修复：app 加退出钩子（atexit/signal）统一 stop_verify + 优雅停止所有 worker；启动时若 8765 已被占用应接管或明确提示，而不是另起实例（runtime/logs/app.log 里有真实的端口占用报错记录）。

### P2 · 一般

**6. 测试套件与 Windows 不兼容**

- pytest 未随 启动Danus.bat 安装；danus/orchestration/cli.py 顶层 import fcntl（Windows 无此模块）导致 orchestration 相关测试无法收集；verify 测试依赖 POSIX .sh fake-codex（WinError 193）；多个测试断言 POSIX 路径。可运行子集 16+ 失败。
- 修复：fcntl 移平台分支、fake codex 改 .py/.bat、路径断言参数化、bat 安装 dev extras。

**7. 文档与实现漂移（codex 版本）**

- PATCHES.md / 使用说明.md 声称 CLI 钉死 0.93.0（chat 接口），但 app/settings.py 实际安装 @openai/codex@latest（实测 0.146.1）且 provider 统一写 wire_api="responses"；CODEX_CLI_VERSION="latest" 常量定义了但从未使用。文档与代码需对齐（尤其 OpenCode Go 套餐说明与实现不符）。

**8. npm root -g 反复以 shell 解析**

- danus/codex.py 每轮 worker 都跑一次；app/settings.py detect_codex 在每次概览轮询（约 8s）也跑一次，均为 shell=True 子进程。建议缓存解析结果（env 变化时失效）。

**9. symlink→copy 降级后内容不同步**

- scaffold.py / launcher.py 的 copytree 副本不会随仓库更新（ensure_agent_home 见文件存在即早退），复制失败被静默吞掉。建议记录 mtime/hash 定期重建，失败写日志。

**10. 细节健壮性**

- loop.py 把所有 OSError 都报成 codex binary not found；
- start_worker 在 Popen 抛异常后仍写 .pid；
- api_set_deadline 不校验数值（字符串可致 500）；
- worker_status 对进程活着但 idle 显示 working；
- _SKIP_PREFIXES 硬编码 2026-（跨年失效）；
- _mcp_config_arg 只转义反斜杠、不转义引号；
- consult.py 的 cost_usd=0.0 硬编码，未实际计费。

**11. 数据一致性/验证可靠性**

- 尾部 4 个 verify-runs 只有 log.md、无 verification.json（中断/超时路径缺重试与告警）；一次 fact_submit 实测出现 [WinError 10054] 远程主机强迫关闭连接（并发验证下验证服务不稳定）；
- 验证器是 LLM 非形式化验证（报告已如实声明非 Lean/Coq 机器证明），重要结论务必人工复核。
